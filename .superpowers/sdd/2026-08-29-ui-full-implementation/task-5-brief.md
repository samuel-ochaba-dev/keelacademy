# Task 5 Brief: Submissions HUD & Verification Verdicts

## Goal
Implement a high-density, real-time command center interface for Submissions & Verdicts (`app/submissions/[id]/page.tsx` and all `components/submission/*` elements) displaying Layer 1 checks, Layer 2 LLM judge results with cited quotes, Layer 3 defend questions, and git submission targets (`app/submit/page.tsx`).

- Modify: `platform/app/app/submit/page.tsx`
- Modify: `platform/app/components/submission/verdict-view.tsx`
- Modify: `platform/app/components/submission/check-list.tsx`
- Create / Modify: `platform/app/components/submission/defend-section.tsx` (if needed)

## Requirements
1. **Real-time Status Banner**:
   - Statuses: `Queued`, `Grading`, `Graded (Passed / Failed)`, `Error`.
   - Visual telemetry: Submission ID, Commit SHA (linked to repo), timestamp, execution time, runner sandbox ID.
2. **Layer 1 Matrix (Deterministic Sandbox)**:
   - Status badge (e.g. `8/8 checks passed`).
   - Detailed check list showing each check ID, description, command executed, assertion type, status icon (emerald check / rose cross), and stdout/stderr snippet drawer if failed.
3. **Layer 2 Matrix (LLM-as-Judge Rubric)**:
   - Overall judge status (`Passed` / `Failed`).
   - Per-criterion cards:
     - Criterion name and requirement text.
     - Status pill (`Pass` / `Fail`).
     - **Exact cited evidence quote** from student submission styled as an annotated code block or quote callout.
4. **Layer 3 Matrix (Defend Your Work)**:
   - Code-specific follow-up questions generated by the verification engine.
   - Code anchors highlighting the specific line / pattern from the student's submission that triggered the question.
   - Response status or explanation input placeholder.
5. **Git Submission Guidance (`app/submit/page.tsx`)**:
   - Step-by-step instructions on pushing code to `origin main` to trigger the webhook intake.
   - Live intake event listener or polling status explanation.
   - Diagnostic guidance for common push issues (wrong branch, untracked files, missing requirements).
