# FAQ — Unit 3.2.1 (JSON mode & structured outputs)

Stub for the unit's unstuck anchors. Answers follow the unit's lesson (learn.md):
constrain generation at the provider, validate at ingestion with Pydantic, and degrade
gracefully (fallback object + logged reason, never a crash or a silent drop).

## My nested-model validation fails with "Input should be a valid dict" {#nested-validation}

Pydantic cannot coerce a JSON *string* into a nested model — a nested field must arrive
as a JSON object (`{...}`), not as a string containing JSON. This usually means the
model returned the nested part as an escaped string (common when you describe the
schema only in the prompt, or use plain JSON mode). Fix it at the boundary: parse the
inner string with `json.loads` before validating, or — the better fix — constrain
generation with a real JSON Schema (structured-output / tool-calling style) so the
nested object is emitted as an object in the first place. If the input genuinely can't
be a dict, that's a validation failure: emit the fallback object and log the reason.

## The model returns valid JSON but the wrong shape (strings where I expect numbers) {#wrong-shape}

This is not a JSON problem; it's a contract problem. `json.loads` succeeding only
guarantees syntax — the lesson's point is that valid JSON of the wrong shape is the
failure mode that crashes your code *furthest from the cause*. Shape is enforced by
`ClaimExtraction.model_validate` (or your equivalent Pydantic model): a string where
you declared `float | None` raises `ValidationError`, and your fallback path produces a
flagged object with the reason instead of garbage downstream. Enum-constrain
categorical fields (`Literal[...]`) and set `extra="forbid"` so wrong keys and values
fail loudly at the boundary too.

## json.loads raises on model output even though JSON mode is on {#json-mode-still-marks}

JSON mode guarantees *syntactically valid JSON only* — no particular schema — and in
practice some models still wrap output in markdown fences or add prose. Two defenses,
both from the lesson: mechanically strip fences as preprocessing (drop the
```` ```json ```` line and closing fence before parsing), and keep `model_validate` on
whatever remains. If parsing still fails, that's a designed failure state, not an
exception: catch `JSONDecodeError` alongside `ValidationError`, emit the fallback
object, and log the fallback with the input's id and reason so nothing vanishes
silently.
